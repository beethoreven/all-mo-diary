# 全心日記 規格草稿

（2026-11-10 起草，持續補充。有疑問當下問清楚；標「待定」的只限使用者明確說之後再談的項目。）

## 1. 基本
- 名稱：中文「全心日記」；英文／專案代號 **all-mo-diary**（diary = 日記）。
- 平台：Android App（介面架構仿 mama-fufood：Flutter，畫面底部有導覽列，上方是各功能頁）。
- 後端：放在共用的 router-backend 裡（見 [router-backend-plan.md](router-backend-plan.md)）。
- Android App ID：**tw.com.tutorarthur.allmodiary**（上架後不能改）。最低 Android 版本照 mama-fufood（minSdk 30）。
- Repo：`all-mo-diary`（meta repo）底下 submodule：`all-mo-diary-app`（Flutter）、`all-mo-diary-web`（入口頁、後台、使用者條款／隱私權政策，GitHub Pages）、`router-backend`（共用後端）。字體另開 public repo，放在 GitHub Release。
- 日期一律用西元年月日，以**台灣時間（Asia/Taipei）**為準。顯示格式：**2026/11/10（二）**（列表、日記畫面都一樣）。
- **底部導覽列**：『行事曆』『篩選』『搜尋』三個頁籤＋反灰的第四個（顯示「即將推出」，不能按）。頁籤 4 的功能之後再定。
- 行事曆可選的年份範圍、換月方式照 mama-fufood（`core/constants.dart` 的 Limits、左右滑動換月）。

## 1.1 第一次打開 App
- 先設定**使用者名稱**（參考 mama-fufood 的 `first_run/first_baby_page.dart`），最多 **8 個字**（一個 emoji 算一個字），前後空白去掉後不能是空的。
- 之後可以在「App 設定」裡改。
- 使用者名稱跟日記一起雲端同步、一起匯出匯入。

## 1.2 頂部列（所有頁籤共用，參考 mama-fufood 的 `ui/shell.dart`）
- 左上：「**＜使用者名稱＞的日記**」（mama-fufood 這裡是可下拉切換的寶寶，全心日記沒有切換）。
- 右上：登入帳號狀態、更多選單（⋮）。
- 進入更多選單的子頁面時，左側換成返回箭頭＋頁面標題（同 mama-fufood）。

## 1.3 更多選單
依序：App 設定、匯入/匯出、使用者條款、隱私權政策、（分隔線）意見回饋。
- 不要 mama-fufood 的「寶寶們設定」「判斷邏輯說明」。
- 匯入/匯出、使用者條款、隱私權政策、意見回饋：照 mama-fufood。

## 2. 資料規則
- **一天最多一篇日記**，不能寫兩篇以上。
- 任何日期都可以寫，包含未來的日期。
- 日記內容：
  - **title**：必填，單行純文字（不套格式），最多 **20 個字**（一個 emoji 算一個字），前後空白去掉後不能是空的。
  - **內文**：可以空。帶格式的文字與圖片，圖片數量不限。

## 3. 頁籤 1：行事曆
- 參考 mama-fufood 的 `lib/ui/calendar/calendar_tab.dart`。
- 每個日期格子只會出現一種標記：有日記就顯示**藍點＋「日記」**兩個字；沒有就空白。
- 點日期：
  - 那天沒有日記 → 直接開「新建日記」畫面。
  - 那天已有日記 → 開「檢視那天日記」畫面。
  - （mama-fufood 一天可以有多筆，會先跳出當天清單；全心日記一天只有一篇，所以不需要這一層。）
- 新建／檢視畫面：見第 6、7 節。

## 4. 頁籤 2：日記篩選
- 上方選日期，結構仿 mama-fufood 的統計頁（`lib/ui/stats/stats_tab.dart`）：
  - 年必選；月預設「不指定」；日在選了月之後才能選。
  - 也就是可以選「整年」「某年某月」「某一天」三種範圍（使用者確認照 mama-fufood，不做任意起迄日）。
- 下方條列符合範圍的日記，每列顯示：**日期（西元年月日）＋日記的 title**。
- 排序：**舊到新**（最早的在最上面）。
- 點某一列：開那一天的日記檢視畫面。
- 沒有結果：列表區空白，正中間顯示明顯、不能點的「沒有結果」（與頁籤 3 相同）。

## 5. 頁籤 3：搜尋
- 上方是搜尋列，由左到右：
  1. **範圍選單**：『全部』（預設）／『標題』／『內文』。
  2. **文字輸入欄**：單行。中英文、數字、標點、空白、emoji 都可以；只擋換行與看不見的控制字元（打不進去）。
  3. **放大鏡按鈕**：按下才正式搜尋（打字時不即時搜尋）。
- 比對規則：「包含」那段文字即算符合。
  - 標題：只找標題包含的。
  - 內文：只找內文包含的。
  - 全部：標題或內文其中之一包含就算。
- 輸入欄是空的（或只有空白）時按放大鏡：不搜尋，提示「請輸入要搜尋的文字」。
- 結果列表與頁籤 2 相同：每列顯示日期（西元年月日）＋title。
- 比對細節：
  - 英文**不分大小寫**。
  - 輸入的**前後空白自動去掉**；中間的空白保留，而且要完全符合。例：搜尋「An Apple」不會找到「AnApple」。
- 輸入長度上限：先定 **10 個字**（一個 emoji 算一個字，照 mama-fufood 用字素叢集計算），之後看介面寬度再調整。
- 排序：舊到新（同頁籤 2）。
- 點某一列：開那一天的日記檢視畫面。
- 沒有結果：列表區空白，正中間顯示明顯、不能點的「沒有結果」。

## 6. 新建／編輯日記畫面
- **全螢幕蓋板**：蓋住所有內容，連底部導覽列也蓋掉。
- 由上到下：
  0. **日期**：最上面一行，顯示這篇日記的日期。新建時只顯示、不能改；**編輯時可以改**（日期選擇器照 mama-fufood）。改成已經有日記的日期時，提示「這天已經有日記了」，日期不改。
  1. **工具列**：只有圖示、不寫文字；**長按圖示跳 toast 說明功能**。一排，放不下的左右滑動。
  2. **標題欄**：單行純文字，工具列的格式不套用在標題上。
  3. **內文**。
- 底部：『取消』『儲存』兩個按鈕。
  - 新建時：只要寫了任何內容，按取消就跳確認對話框。
  - 編輯時：只要改了任何東西，按取消就跳確認對話框。
  - 儲存：沒有 title 時提示「請輸入標題」，不儲存。存在手機本機；另有「放上雲端」的設定（第 8 節）。儲存後**切換成這篇的檢視畫面**（第 7 節）。
  - 手機的返回手勢／返回鍵 = 按『取消』。
- **自動草稿**：新建或編輯時，每幾秒在手機上存一份草稿（不同步、不算日記、不出現在行事曆）。App 被系統關掉、沒電後，下次打開問「要接著寫上次沒儲存的內容嗎？」。按儲存或確認取消後刪掉草稿。

### 6.1 工具列
| 工具 | 選項 | 預設 |
|---|---|---|
| 復原／取消復原 | 兩個按鈕，放工具列最前面 | — |
| 字體大小 | 下拉選單：8、10、12、14、16、18、20 pt | 12 pt |
| 字體 | 選單 | Noto Sans TC（免費，SIL Open Font License）。「新增字體」由後台管理，做法參考 mama-fufood 的副食品清單版控（之後細談） |
| 粗體 | 開／關 | 關 |
| 斜體 | 開／關 | 關 |
| 底線 | 開／關 | 關 |
| 刪除線 | 開／關 | 關 |
| 底色 | 淡紅、淡黃、粉藍、粉綠、灰色、黑色、無色 | 無色 |
| 字的顏色 | 深紅、亮黃、深藍、深綠、白色、黑色 | 淺色主題黑色、深色主題白色 |
| 加上圖片 | 只能從手機相簿選 | — |
| 預設 | 有選取時，選取的文字改回預設格式；沒有選取時，游標之後輸入的內容改回預設格式 | — |

- **套用規則**：
  - 有選取（框起來）文字時改設定 → 套用到選取的文字。
  - 沒有選取時，游標後面接著打的字，沿用游標前面那個字的格式。
- **圖示**：用 Flutter 內建的 Material Icons（Apache 2.0 授權，可自由使用，樣式與 Word 類似：format_bold、format_italic、format_underlined、strikethrough_s、format_color_fill、format_color_text、format_size、font_download、image、format_clear）。Word 本身的圖示屬於 Microsoft，不直接拿來用。

### 6.2 圖片
- 從手機相簿選。
- 不管原檔多大，都先壓縮：**高度 = 畫面高度的 1/3**，寬度依原比例；若這樣寬度超過螢幕，改成**寬度 = 螢幕寬**，高度依比例縮小。存的就是壓縮後的檔案。
- 一篇日記的圖片數量不限。
- 點圖片可以放大檢視，放大的也是壓縮後的那張。
- 照 mama-fufood：先依方向資訊轉正，再移除 EXIF（含拍攝地點）。

## 7. 檢視日記畫面
- 版面與新建畫面相同，但內容全部鎖住、不能編輯；**工具列隱藏**（只有日期、標題、內文）。
- 底部按鈕：『返回』『編輯』『刪除』。
  - 返回：關閉畫面。手機的返回手勢／返回鍵 = 按『返回』。
  - 編輯：切換成編輯狀態（第 6 節），底部按鈕變回『取消』『儲存』。
  - 刪除：
    1. 第一次對話框：確認是否刪除。
    2. 第二次對話框：使用者要輸入「刪除日記」四個字，才會真的刪除。
    3. 刪除後關閉畫面，回到原本的頁籤。

## 8. App 設定（參考 mama-fufood 的 `more/settings_page.dart`）
- **使用者名稱**：可修改（規則同第 1.1 節）。
- **顯示**：週起始日、主題（深色／淺色／跟隨系統）照抄。
  - 不要 mama-fufood 的兩個「選單自動選定」設定。全心日記的選單只有字體與顏色，一律「點了就選、點外圍就關閉」。
- **雲端**：照抄 mama-fufood（「日記與雲端同步」開關＋最後同步時間、「圖片存到雲端」開關、現在同步）。
  - **省空間原則**（使用者 2026-11-11 決定）：在資料不會出錯的前提下，盡量把資料放雲端省手機空間。
  - **兩個開關，照 mama-fufood 分開**（使用者 2026-11-11 決定）：
    | 開關 | 管什麼 | 雲端位置 | 手機上 |
    |---|---|---|---|
    | 日記與雲端同步 | 日記的日期、標題、內文含格式、使用者名稱 | 只有本 App 讀得到的隱藏區（`drive.appdata`） | 一樣留完整的一份 |
    | 圖片存到雲端 | 圖片 | 看得到的「全心日記/圖片」資料夾 | 上傳並核對無誤後刪掉，要看時再下載 |
    兩個都開時：手機有文字＋格式，雲端有文字＋格式＋圖片。只開其中一個也可以。
  - 兩支手機同時修改同一篇日記的情況先不處理（使用者 2026-11-11：先不考慮）。
  - **圖片**：照 mama-fufood，上傳到雲端硬碟「全心日記/圖片」後核對 MD5，一致才刪手機上的那一份；之後要看時從雲端下載到暫存區。沒網路時那張圖顯示「需要網路才能顯示」。
    - 日記內文裡存的是圖片的**編號**（加寬高），不是圖片本身；圖片檔另外存（手機或雲端）。所以離線編輯不會弄丟圖片：顯示不出來的圖片仍是內文裡的一個方塊（「需要網路才能顯示」，大小同原圖），可以跟著文字移動；連線後依編號下載顯示。只有使用者自己把那個方塊刪掉，才算刪除那張圖。
    - 離線新增的圖片先存在手機，連線後才上傳，核對無誤才刪手機那一份。
    - 雲端上的圖片**不會因為某一支手機的內文不再引用就立刻刪除**：先標記，等同步確認所有版本（包括衝突時被保留的那一版）都沒有引用才刪，避免兩支手機各改一版時，保留下來的那一版的圖片已經被刪掉。
  - **文字**（日期、標題、內文含格式）：手機與雲端**各留完整的一份**。曾考慮「手機只留純文字、格式只在雲端」，但一年的日記文字只有幾 MB，省不了多少；而且離線編輯一篇格式不在手機上的日記會弄丟格式，違反「資料不會出錯」的前提，所以不這樣做（使用者同意全留）。
  - 草稿、主題、週起始日、登入資料、字體檔、診斷記錄只在手機。
- **公用資料與版本**：公用資料只有**字體清單**（只抓字體名稱清單，不抓字體檔）；「檢查更新」、App 版本、開放原始碼授權照抄。
- **字體設定**：進入第 9 節的字體設定頁。

## 9. 字體設定頁
- 兩個可以收合的區塊，合起來就是雲端字體清單的全部項目：
  - **已安裝字體**：每項旁邊有「刪除字體」圖示。內建的 Noto Sans TC 永遠在這裡，**沒有刪除圖示**。
  - **未安裝字體**：每項旁邊有「安裝字體」圖示，按了從雲端下載字體檔。
- 每個字體旁邊顯示**安裝後大小**（MB，佔手機多少空間）；未安裝的項目另外用小字標下載大小。
- **授權標示**：每個字體顯示「有授權／未確認授權」（後台設定，只是標示）。
- **顯示名稱**：不讀字體檔內建的名稱，用後台設定的名稱。字體存到手機後，App 自己保存「字體 ID → 顯示名稱」的對應。
- 日記裡記的是字體 ID。

### 9.1 字體出問題時
- **打字或套用到選取文字時，有字是這個字體沒有的**：支援的字照套，不支援的那幾個字改用預設字體（Noto Sans TC），跳 toast 說明是哪幾個字不能套用。
- **打開的日記用到這支手機沒裝的字體**（已刪除，或從別支手機同步來的）：先用預設字體顯示，跳 toast「這篇用到未安裝的字體：XX」。日記裡記的字體不變，裝回來就恢復。
- 以上狀況都寫進診斷記錄（第 10 節）。

## 10. 意見回饋與診斷記錄
- 意見回饋頁、診斷記錄（log）機制完全照抄 mama-fufood（App 端 `core/log.dart`、`more/feedback_page.dart`；後端 `/api/v1/feedback`）。
- 字體無法套用的事件要記錄（第 9.1 節）。

## 11. 後台
- 大方向全抄 mama-fufood：入口頁面右上角登入，登入後（管理員）才有後台入口；App 設定（最低版本、強制更新）、意見回饋管理、管理員管理照抄。
- **公用資料只有字體**。每個字體：ID、名稱（顯示名稱）、檔名、排序、停用、刪除、**授權標示**（有／未確認）。版控照 mama-fufood 的副食品清單（草稿 → 發布；ID 永遠不可改、不可重用）。
  - 另外記：檔案大小、SHA-256（App 下載後核對）。
  - **授權只做標示，不擋上傳**（目前非商用）。⚠️ 如果哪天要商用，字體功能要重新檢討（只能放允許再散布的字體）。

### 11.1 字體檔（2026-11-10 決定）
- **放 GitHub Releases**（使用者不想綁信用卡；R2 啟用幾乎一定要綁卡）。字體專用的 **public** repo，App 直接從 GitHub 下載，不經過 Render。
  - ⚠️ 檔案是公開的：「未確認授權」的字體等於公開散布。目前非商用、使用者接受；商用前要重新檢討。
  - 不放資料庫（Neon 免費空間塞不下）、不放 Google 雲端硬碟（同一檔案下載太多次會被暫時鎖住；service account 沒有空間）。
- **一個字體只有一個檔**：粗體由系統加粗；可變字重字體（例如 Noto Sans TC 的 VF 檔）用字重軸。
- **上傳上限：解壓後的字體檔 120 MB**（瘦身後最大的全字庫正楷體約 56 MB）。App 安裝超過 50 MB 的字體時，先提醒大小再下載。
- **上傳前先瘦身**：`tools/reduce_font.py`（在使用者的 Mac 上跑）。重新做 CFF 子程式化，大小約減半，字形差異約 0.004 單位（1000 單位的 em），肉眼看不出；再 gzip。輸出 `<名稱>.otf`（手機安裝的檔）、`<名稱>.otf.gz`（上傳／下載的檔）、`<名稱>.json`（大小、SHA-256）。預設輸出到 `reduced_fonts/`。
- **後台上傳**：後台有選檔功能，選 `.otf.gz` 上傳 → **經過 backend** → backend 邊收邊轉傳到字體 repo 的 GitHub Release，同時寫進字體清單草稿，發布後 App 就能用。
  - backend 檢查：副檔名、大小上限、解壓後的檔頭是 OTF/TTF；邊收邊算 SHA-256，不整份讀進記憶體。
  - backend 需要一把只對字體 repo 有寫入權的 GitHub 金鑰（fine-grained token），放環境變數，不進 git。
  - 待實作時驗證：Render 對上傳大小與請求時間有沒有限制；gunicorn timeout 要夠長；上傳會佔住共用服務的一個執行緒幾十秒到幾分鐘。
- **App 下載**：下載 `.otf.gz` → 邊下載邊用 gzip 解壓寫檔 → 核對解壓後 `.otf` 的 SHA-256，一致才算安裝完成。字體只在需要顯示時才載入記憶體，不在啟動時載入全部已安裝字體。

### 11.2 常見中文字體大小（2026-11-10 查）
| 字體 | 單檔大小 | 備註 |
|---|---|---|

## 13. 實作備註（2026-11-11，第一版）
- **外觀**：結構照 mama-fufood，主題色改成鵝黃色（#F6D365）；淺色主題的文字與圖示改用較深的金色（#8A6500），黃色太淺不能當字。主題預設「跟隨系統」。
- **日記的紙**：淺色主題米白色（#FAF6EC）、預設字色黑色；深色主題深灰色（#2B2B2B）、預設字色白色（使用者 2026-11-11 決定）。「預設字色」在日記裡不存顏色，所以同一篇日記在兩種主題都看得清楚；在字色選單選到「這個主題的預設色」（淺色選黑色、深色選白色）等於回到預設，選另一個（例如深色主題選黑色）才會固定成那個顏色。
- **字體大小**：日記裡存 pt 數字（"14"），畫面上每 1 pt = 4/3 個邏輯像素（網頁 pt→px 的比例），12 pt 看起來跟一般 App 內文差不多。
- **編輯器**：flutter_quill 11.6.0（MIT），內文存成 Quill Delta（JSON）；另存一份純文字給搜尋用。
- **選單**：年、月、日、字體大小、字體、搜尋範圍都是「點了就選、點外圍就關閉」的清單；底色與字色是色塊對話框。年／月／日三個按鈕用較小的字排在同一行，螢幕太窄時整排一起縮小，不換行。
- **圖片**：存在手機 `files/images/<id>.jpg`；先轉正、去 EXIF，再縮成畫面高度的 1/3（太寬就以螢幕寬為準）。沒有日記或草稿用到的圖片，在 App 啟動、儲存、刪除時清掉（一分鐘內新加的不清，避免剛選的圖被刪）。
- **Android 自動備份**只備份資料庫（`files/db/`），圖片不備份（25 MB 上限），之後靠「圖片存到雲端」保護。
- **已做**（2026-11-11）：App 圖示（`tool/icon/make_icon.py`）、使用者條款與隱私權政策（草稿，`assets/texts/`）、App 設定的 App 版本與開放原始碼授權。
- **Google 登入**（2026-11-11）：照 mama-fufood 與 google-auth skill。登入時用 Google 的 ID Token 跟後端（`POST /diary/api/v1/session`）換一張 App 通行證（無狀態、180 天、超過 30 天由每日檢查換新），帳號與通行證存在手機資料庫，重開 App 直接是登入狀態、**不呼叫 Google 的自動登入**。後端只收自己的通行證，不收 Google ID Token 當持續憑證。網頁用戶端 ID 與後端網址（`https://router-backend-3hl2.onrender.com/diary`）寫在 App 的 `lib/core/env.dart`（都不是秘密）。
- **雲端、後端、後台**（2026-11-11 第二批，全部照 mama-fufood 的做法）：
  - **雲端同步**（`services/sync_engine.dart`）：每篇日記在 `drive.appdata` 一個檔（`amd_diary_<id>.json`），使用者名稱一個檔（`amd_profile.json`）；比修改時間，新的贏；刪除留「已刪除」紀錄讓別支手機也刪。打開 App／回到 App 時同步（最多一分鐘一次），儲存、刪除後也同步；失敗會自動重試。換了 Google 帳號會擋下來，請使用者換回或關掉再打開。
  - **雲端圖片**：同一次同步先處理日記、再處理圖片；只有這支手機自己的圖片、而且已經沒有任何日記或草稿用到，才刪雲端那一份。第 8 節寫的「先標記、等所有版本都確認沒用到才刪」是為了兩支手機同時改同一篇，這個情況使用者決定先不處理，所以第一版沒有做延後刪除。關掉「圖片存到雲端」時先把圖片全部下載回手機才關。
  - **每日檢查**（`services/daily_check.dart`）：每天第一次打開 App 時檢查最低版本（強制更新畫面）、公告、字體清單，順便把超過 30 天的 App 通行證換新。失敗時隔 2 小時再試，一天最多 5 次。
  - **字體**：App 下載 `.otf.gz`、邊下載邊解壓、核對 SHA-256，存在 `files/fonts/<id>.otf`；用到才載入。缺字的判斷讀字體檔的 cmap 表（format 4/12）。
  - **意見回饋與診斷記錄**：照抄 mama-fufood（記錄檔遮掉使用者名稱與 Google 帳號名稱；沒網路先放待送清單，一天最多重試 5 次）。
  - **匯入/匯出**：整份加密（AES-256-GCM），存到使用者雲端硬碟「全心日記」資料夾，檔名 `全心日記_匯出_YYYYMMDD_HHMMSS.amd`；金鑰在 `drive.appdata`，只有同一個 Google 帳號能匯入。匯入時同一篇保留較新的版本；同一天手機已經有另一篇，問使用者保留哪一篇。
  - **後端**（router-backend 的 `apps/diary`）：`/api/v1/session`（換通行證）、`/api/v1/check`（每日檢查）、`/api/v1/feedback`；後台 API 在 `/api/admin/*`。字體上傳邊收邊轉傳到 GitHub Release（不整份放記憶體），同時算下載檔與解壓後字體的 SHA-256。
  - **後台**（all-mo-diary-web 的 `admin.html`）：字體（新增、改名、排序、授權、停用、上傳、發布）、App 版本（最低版本、強制更新原因、更新連結、公告）、意見回饋、管理員、系統（快取重新載入）。
  - **還沒用真的檔案驗證**：Render 上傳大檔（50 MB 以上）會不會被切斷。程式這邊：上傳上限 130 MB、gunicorn 是多執行緒 worker（timeout 不會砍掉還在傳的請求）、轉傳 GitHub 的讀取逾時 10 分鐘。
